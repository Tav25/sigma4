# SIGMA4 v0.1.21 — S15. Расстановка стоек по конструктивным узлам

**Дата:** 2026-11-06. **Ветка:** \`sigma4\`. **Исходный коммит:** \`d1d6c5ed575790bf0e8a336cb573d23fe703eae4\`.

## Конструктивная методика

Этап 2 аудита по Larry Haun, *The Very Efficient Carpenter*, глава *Framing Walls*, раздел *Detailing*, страницы 94–97, особенно *Detailing Walls for Stud Location* (стр. 96): сначала отмечаются углы, проёмы и примыкания, затем рядовые стойки раскладываются с повторным началом шага после каждого проёма и канала. У Хона обычно 16 in (406,4 мм) o.c., но в SIGMA4 шаг **параметризован** существующим профилем стены (сейчас 600 мм снаружи, 400 мм внутри); это НЕ утверждение о соответствии выбранного шага нормативам для заданной нагрузки.

## Изменение алгоритма

Ранее \`generateWallPanel\` заполнял всю стену регулярной сеткой, а генераторы окон/дверей/примыканий удаляли перекрывающиеся стойки. В режиме построения каркаса из **2D-плана** (\`floorPlan.frame.built\`) теперь:

1. \`generateWallPanel(requiredFirst)\` создаёт нижнюю и обе верхние обвязки и **две торцевые стойки**, но не заполняет ими всю длину.
2. \`generateWallWithOpenings\` / \`generatePartitionWithDoors\` устанавливают пакеты king/jack стоек, дверные/оконные перемычки и обязательные подоконные опоры.
3. \`connectPerimeterCorner\`, \`addPartitionBacking\` ставят углы и трёхстоечные приёмные каналы Хона на реальные места; \`connectTopPlateLaps\` устраивает нахлёсты второго слоя обвязок.
4. Новый \`detailLinkedStuds\` строит «станции» из king-стоек каждого проёма и двух боковых стоек каждого приёмного канала. Между конструктивными станциями, начиная от торцевых стоек, размещает рядовые полноразмерные стойки на заданном шаге. После каждой станции шаг **начинается заново**, а не продолжается через проём/канал. Если последняя стойка вплотную подошла бы к обязательной, она отодвигается на ширину доски.
5. Короткие стойки над дверными и оконными перемычками и под подоконниками получают **независимую разметку**, отложенную от краёв проёма. Исключено появление полноразмерной рядовой стойки внутри проёма. Сохраняются ранее созданные обязательные крайние подоконные опоры.
6. Стабильные производные ID \`:stud-layout-<x>\`, \`W01-cripple-top-layout-<x>\` вычисляются из координат в мм. JSON точек/отрезков/проёмов не изменяется, результат воспроизводится после импорта.
7. Сохраняются исходные структурные торцевые стойки \`:stud-01/02\`, так что corner / T / X взаимные связи не теряются. Реальное пересечение обязательных стоек или невозможный пролёт не скрывается и вызывает ошибку сборки.

**Обратная совместимость:** автономный старый 3D-режим и его нумерация \`stud-01, stud-02, ...\` оставлены без изменений; новый метод применяется ко всем наружным стенам и перегородкам, связанным с каноническим 2D-планом. Отдельный этап переноса автономного режима будет возможен после его рефакторинга.

## Проверки

Новый \`stud-detailing.test.ts\` проверяет: обязательные стойки перед заполнением; повторный шаг от king и Haun channel; отсутствие наложений; окна, двери, ворота, оконные короткие стойки; Г/Т узлы и реальный горизонтальный срез, стабильность импортируемого JSON.

Существующие модульные регрессии \`wall.test.ts\` / \`window.test.ts\` для standalone не меняются. \`browser-smoke.mjs\` дополнительно проверяет, что в проекте **9×6 м** с кладовой и дверью D01 новый шаг появляется только в свободных пролётах, короткие стойки над дверью создаются, а исходные проёмы сохраняются.

**Статус CI:** определяется фактическим результатом GitHub Actions. До успешного завершения нельзя считать этап принятым.

## Ограничения и нормативы

Разметка **геометрическая**, не расчётная. Нет автоматического учёта классов пиломатериалов, снеговых/ветровых нагрузок, жёсткости обшивки, допустимого шага из региональной IRC/CSA таблицы, а также контроля опирания швов листовой обшивки. Шаг 400/600 мм не автоматически допустим для всех несущих стен. \`engineeringStatus = not_evaluated\`.

**Регламент:** зафиксированный исходный SHA; только ветка \`sigma4\`; без переписывания истории; независимый JSON — единственный источник истины; проверки TypeScript + unit + build + Chromium; результат пользовательской приёмки перед следующим этапом.
