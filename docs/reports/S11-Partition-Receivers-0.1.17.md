# SIGMA4 v0.1.17 — узел примыкания внутреннего каркаса к наружной стене

Дата: 2026-11-06. Ветка: `sigma4`. Исходный SHA: `9438157d8a4020557db0d925b92721a26fe3e5d2`.

## Основание
Пользователь предоставил схему сверху: наружная стена обозначена двумя продольными границами (белый), поперечные стойки наружного каркаса оранжевым; внутренняя перегородка — серым, её стойки зелёным. Торец перегородки должен встречать подготовленные поперечные закладные в наружном каркасе, а не пустую полость.

## Реализация
1. `partitionSides`: соединения теперь определяются по полному набору смежных осевых сегментов в узле. Т-узел после разбиения графа имеет два коллинеарных участка, составляющих непрерывную стену; входящий перпендикулярный отрезок подрезается до её поверхности на половину толщины. В крестовом узле непрерывным считается ось X, оба Z-ответвления подрезаются. Угол L сохраняет ранее принятый алгоритм для совместимости.
2. `validatePlanFrame`: конец графового участка с продолжением другой стеной на той же прямой не считается недопустимым близким к углу примыканием — там физически имеется опора; прочие ограничения проёмов/углов не ослаблены.
3. `addPartitionBacking`: у каждого реального торцевого примыкания перегородки к наружной стене генерируются **две полноразмерные поперечные закладные-стойки**, отнесённые от оси примыкания по обе стороны торцевого элемента. Для стандартной перегородки 100 мм и стойки 45 мм их центры отстоят от оси на 27,5 мм. Длина высотной стойки учитывает нижнюю и верхние обвязки наружного каркаса. Они используют реальную глубину наружной стены 145 мм. Стойки наружной сетки, пересекающиеся с новыми закладными, заменяются в производной `assembly`, не изменяя источников JSON; критичные конструктивные элементы (дверные стойки, угловые закладные, другие узлы) нельзя заменять или пересекать.
4. Торцевая стойка внутренней стены и обе закладные имеют двусторонние `connectionIds`. Внутренний Т/Х-узел использует уже существующую торцевую стойку разрезанной сквозной стены, без создания дублирующейся доски на том же месте.
5. 2D-граф, наружные габариты, стандартная сетка, двери, сохранение/импорт JSON, откат/повтор изменений и 3D проекция остаются в существующей архитектуре. Новые закладные появляются только как производные 3D-элементы.

Добавлены `partition-connection.test.ts`: гараж 10 × 7 м, точное положение двух закладных, физический контакт торцевой стойки с закладными в 3D, отсутствие пересечения тел, узел с существующей стойкой на шаге 600 мм, Т- и крестообразные графовые соединения. GitHub Actions выполняет `npm ci`, строгую типизацию, модульные тесты, сборку, Chromium/browser-regression с сохранением скриншотов. **Не считать проверку пройденной до фактического завершения GitHub Actions.**

## Границы реализации
- Это **конструктивная геометрия**, а не сертифицированный расчёт крепежа и нагрузок. Тип крепежа, шаг крепежа, несущая способность и нормативный регион отдельно не назначены, engineeringStatus по-прежнему `not_evaluated`.
- Поддерживаются ортогональные стены. Специальные необычно толстые перегородки свыше типовых 89–145 мм требуют отдельной проработки опор и обшивки; две закладные не заменяют инженерный расчёт.
- Проверка физического контакта относится к конкретным сценариям теста; полноценный пространственный валидатор всей сборки остаётся отдельной задачей.
