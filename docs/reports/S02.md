## 2. ВЫПОЛНЕННЫЕ РАБОТЫ

### Что реализовано

1. **ProjectStore** (`src/core/ProjectStore.ts`) — центральное хранилище состояния проекта:
   - Хранит текущий `ProjectDocument`, номер ревизии, историю изменений (до 100 действий)
   - Подписчики на изменение состояния (используется `useSyncExternalStore` в React)
   - Транзакционная модель: `beginTransaction` / `preview` / `commitTransaction` / `rollbackTransaction`
   - Полная история с undo/redo

2. **Командная система** — 10 типов команд для редактирования параметров версии 0.0.14:
   - `SET_PROJECT_NAME` — изменение имени проекта
   - `SET_WALL_LENGTH` / `SET_WALL_HEIGHT` / `SET_STUD_SPACING` — параметры стены
   - `SET_OPENING_POSITION` / `SET_OPENING_WIDTH` / `SET_OPENING_HEIGHT` / `SET_WINDOW_SILL_HEIGHT` — параметры проёмов
   - `SET_MARKER_SETTINGS` — настройки маркеров
   - `REPLACE_PROJECT` — полная замена документа (импорт)
   - `ADD_OPENING` / `REMOVE_OPENING` — добавление/удаление проёмов (S02.2)

3. **Атомарное применение изменений:**
   - Создание кандидата из текущего документа
   - Применение команды только к кандидату
   - Валидация исходных параметров (`validateSourceParameters`)
   - Пересчёт сборки через `buildProjectSnapshot`
   - Полная валидация через `FrameValidator`
   - При ошибке: отклонение, модель не меняется, ревизия не увеличивается

4. **Исправление русскоязычных сообщений валидатора (S01.15):**
   - "Ширина проёма должна быть положительной" (было "должно быть положительным")
   - "Высота проёма должна быть положительной"
   - "Длина стены должна быть положительной"
   - "Высота стены должна быть положительной"
   - "Толщина стены должна быть положительной"
   - "Плотность должна быть положительной"
   - Все размерные сообщения используют правильный род

5. **Интеграция с App.tsx:**
   - Устранены дублирующие React-состояния (`useState` для длины, высоты, шага, окон)
   - Все параметры читаются из `store.getSnapshot()`
   - Изменения отправляются через `store.dispatch(command)`
   - Подключены Undo/Redo кнопки в интерфейсе
   - Добавлен экспорт/импорт JSON через Store

### S02.3 Исправления (Acceptance Corrections)

1. **История изменений:**
   - Разделены номер ревизии (монотонный счётчик) и индекс истории
   - `addToHistory` корректно обновляет `historyIndex` после добавления записи
   - После Undo/Redo правильно определяются `canUndo`/`canRedo`
   - Новая команда после Undo очищает ветку Redo
   - При обрезке истории (`trimHistory`) корректно корректируется `historyIndex`
   - История ограничена 100 отменяемыми действиями
   - Ревизия монотонна и не повторяется при Undo/Redo

2. **Транзакции:**
   - Добавлено поле `lastPreviewSuccess` в `TransactionState`
   - `preview` устанавливает `lastPreviewSuccess` в true/false
   - `commitTransaction` проверяет `lastPreviewSuccess` — если false, отклоняет с ошибкой `INVALID_TRANSACTION_STATE`
   - `commitTransaction` повторно валидирует `previewDocument` перед принятием
   - Пустая транзакция не создаёт лишнюю запись истории
   - `SET_PROJECT_NAME` в транзакции корректно применяется

3. **Валидация команд:**
   - `validateSourceParameters` расширен геометрическими проверками:
     - `OPENING_OUT_OF_BOUNDS` — проём выходит за границы стены
     - `OPENINGS_FRAME_OVERLAP` — перекрытие фреймов проёмов
     - `OPENING_TOO_TALL` — проём слишком высокий для стены
   - Конкретные коды ошибок возвращаются вместо общего `VALIDATION_FAILED`
   - Проверка выполняется до генерации сборки

4. **Импорт:**
   - `importJson` корректно применяет длину стены из импортированного JSON
   - При ошибке импорта текущий проект полностью сохраняется
   - Повреждённый JSON не вызывает необработанных исключений

### Источники данных

- **Единственный источник:** `ProjectStore.document` (ProjectDocument)
- **Чтение:** `getSnapshot()` — глубокая копия, защищена от мутации (`deepFreeze`)
- **Запись:** только через `dispatch(command)` или транзакции

### JSON Schema

- Не изменялась (`schema/sigma4-project.schema.json` v1.0.0)
- Все команды работают с существующими полями

### Правила валидации

- `validateSourceParameters()` — проверяет исходные параметры + геометрию (OPENING_OUT_OF_BOUNDS, OPENINGS_FRAME_OVERLAP, OPENING_TOO_TALL)
- Используется до генерации сборки для раннего отклонения
- Полная валидация после `buildProjectSnapshot` остаётся без изменений
