# SIGMA4 v0.1.26 — S20. Единый алгоритм дверных проёмов

**Ветка:** \`sigma4\`. **Исходный SHA перед изменениями:** \`5ab7df2e0cf73d6a7b730cb0ddfa9778d0a2fe73\` (v0.1.25).

## Исправленная архитектура

Ранее \`partition-door.ts\` строил ненесущие двери собственным кодом, а \`window.ts:applyDoorOpening\` — наружные/гаражные двери другим набором формул. Дублировались расчёт king-стоек, сегментация нижней обвязки и формирование перемычки.

**Теперь один модуль** \`src/core/door-frame.ts\` содержит:
- \`doorProfile\`: выбор сохраняемых конструктивных профилей. \`nonbearing-flat\` для дверей ненесущей внутренней перегородки, \`bearing-double-preview\` для наружной двери и \`garage-engineered-preview\` для гаражных ворот.
- \`doorFrameMembers\`: единая геометрическая последовательность: проверка исходного проёма, king-стойки по границам выбранного профиля, опоры jack при необходимости, одна горизонтальная плоская либо две предварительные вертикальные доски перемычки.
- \`doorBottomPlates\`: одинаковое геометрическое правило разрыва нижней обвязки на каждом дверном проёме, при этом сохраняет исторические ID для наружной и внутренней стены.

\`partition-door.ts\` и \`window.ts:applyDoorOpening\` используют этот общий источник логики. Соседние функции генерации окон, рядовых стоек, верхних обвязок и трёхстоечных примыканий не изменены.

## Сохранённые конструктивные различия

- **Дверь ненесущей перегородки**: 2 полноразмерные king-стойки; 1 flat header (45×100 мм в принятом метрическом модуле), без jack-стоек; разрыв нижней обвязки. Короткие стойки над дверью продолжают рассчитываться на этапе \`detailLinkedStuds\`.
- **Наружная дверь**: king-стойки, по одной jack на сторону, 2 доски вертикальной предварительной перемычки. Профиль S16 по глубине/количеству jack применяется после создания основы к связанным 2D-планам.
- **Гаражные ворота**: тот же движок с количеством jack-стоек и глубиной предварительной перемычки из \`GarageDoorSpec\`; инженерный статус \`not_evaluated\`.

Важно: один программный движок не означает одинаковую древесину и крепление. Все наружные несущие профили **предварительные**: нормативные расчёты нагрузок, марка древесины, крепёж и возможная внутренняя несущая стена остаются отдельными задачами.

## Совместимость

- Не изменён формат авторского JSON: старые \`floorPlan.frame.openings\` и параметры walls остаются источником истины.
- Сохранены ID \`D01-header\`, \`D02-header-1/2\`, \`jack-left/right\` и исторические имена частей нижней обвязки.
- Детерминированная сборка проверяется повторной генерацией; прежние модульные тесты окон/дверей/ворот остаются обязательными.

## Тесты и контроль предыдущего этапа

\`src/core/door-frame.test.ts\` проверяет оба профиля, king-геометрию, количество jack, горизонтальные доски, два дверных разрыва, исходные ID, детерминизм и запрет некорректных настроек.
\`scripts/browser-smoke.mjs\` проверяет существующие две двери D01/D02 во внутреннем сквозном прогоне и внешний проём W01: разные конструктивные профили, одинаковые правила и валидность экспортированного JSON.

В предыдущем коммите v0.1.25 CI имел **1 устаревшее ожидание** в \`top-plate-laps.test.ts\`: число физических модулей в Т-узле 3 вместо 2. Тест приведён к утверждённой схеме «одна сквозная и одна примыкающая стена», а проверка физического нахлёста оставлена.

Результаты CI записываются только по фактическому прогону для этой версии, не заявляются заранее.

## Регламент

Изменения только в ветке \`sigma4\`. Без переписывания Git. Архитектура JSON как единственный источник истины сохранена. Этап выполнен без перехода к несущему расчёту и без изменения пользовательского интерфейса.
