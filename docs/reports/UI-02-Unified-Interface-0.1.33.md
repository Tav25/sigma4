# SIGMA4 UI-02 — единая система интерфейса (0.1.33)

Ветка: `ux-audit-0.1.32` (продолжение UX-01). Реализация не затрагивает инженерные алгоритмы, хранилище/формат JSON, каркасные соединения или валидацию.

## Правила оформления

- Одна ширина левых панелей для плана 2D и каркаса 3D: **302 px** при окне шире 1000 px, **260 px** при 701–1000 px. Разрез использует ту же левую панель 3D.
- До 700 px в обоих рабочих пространствах редактор занимает верхнюю область, а инспектор становится нижней прокручиваемой панелью на всю ширину экрана (максимум 32vh).
- Один набор CSS-токенов в `src/ui-theme.css`: `--ui-sidebar-width`, `--ui-bg`, `--ui-surface`, `--ui-border`, `--ui-text`, `--ui-muted`, `--ui-accent`, `--ui-accent-hover`, `--ui-accent-light`, `--ui-focus`, `--ui-radius` и семантические success/error.
- Общие кнопки: минимальная высота 38 px, радиус 8 px; три варианта — основной (заливка), вторичный (светлый), текстовый/опасный. Те же параметры используются в инструментах плана, ручных операциях 3D, настройках сечения, масштабировании и сбросе камеры.
- Общие поля: высота 38 px, радиус 8 px, типографика 13 px, одинаковая рамка, цвет текста и индикация фокуса. Большое поле длины плана сохраняет усиленную типографику как иерархический акцент.
- Общие заголовки, информационные панели, карточки свойств и дерево проекта. Верхняя панель остаётся тёмным контрастным вариантом того же набора компонентов.
- Весь текст/подписи и выбор технологических цветов (отметки осей, дверей, древесины в секции, визуализация) **не меняются функционально**; семантические цвета ошибок сохраняются.
- Версия `0.1.33`; файловый импорт, экспорт, Undo/Redo и доступность команд прежние.

## Проверки

GitHub Actions: `npm ci`, `npm run lint`, `npm test`, `npm run build`, браузерный `ux-smoke.mjs` и полный `browser-smoke.mjs`. В UX smoke добавлены реальные CSS-проверки равенства ширины, фона, границы, padding и стилей кнопок на десктопе, в размере 900px и на мобильном 390px; сравниваются также элементы горизонтального разреза. Скриншоты приложены к CI.

Технические правила: работать в отдельной ветке, исходный SHA закреплён; не перезаписывать историю, никаких правок инженерных алгоритмов, JSON остаётся единственным источником состояния. Перед приёмкой убедиться, что CI полностью зелёный.
