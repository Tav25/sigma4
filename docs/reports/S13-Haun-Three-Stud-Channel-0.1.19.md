# SIGMA4 v0.1.19 — корректный трёхстоечный узел примыкания по Ларри Хону

Дата: 2026-11-06. Ветка: \`sigma4\`. Исходный Git SHA: \`5c1930a4918c68c162c0d257d51c8513fe7031c6\`.

## Почему заменён узел 0.1.17

Ранее алгоритм ставил две отдельные 45×145-мм стойки в наружной стене прямо под торец перегородки и не ставил центральную доску плашмя. Это **не соответствует** 3-stud channel, описанному Ларри Хоном. Вместо этого нужен узел, состоящий из двух обычных продольных стоек полного профиля наружной стены и **третьей сплошной стойки, поставленной плашмя между ними со стороны внутренней перегородки**.

Ориентир: Larry Haun, *How to Build a House*, раздел *Building Corners and Channels* (стр. 97); *The Very Efficient Carpenter*, раздел *Building Walls*, рис. D на стр. 102. Альтернатива из источника — ladder backing из нескольких **коротких** блоков, это другой вариант и здесь не включён.

## Воспроизводимая геометрия (миллиметры, вид сверху, отметка 1200)

Пример: наружная стена 45×145, перегородка 45×100, ось примыкания U = 4000 вдоль наружной стены. Три производных элемента с одинаковой высотой 2565 мм:
- Левая стойка: сечение 45×145; центр U = **3927,5**.
- Правая стойка: сечение 45×145; центр U = **4072,5**.
- Третья, **плашмя**: сечение доски 45×100; в горизонтальном сечении занимает U = **3950…4050** и внутреннюю полосу глубиной 45 мм со стороны помещения; \`orientation.mode='y'\`, \`roll=90°\`. К ней торцом без зазора примыкает зелёная концевая стойка 45×100 внутренней перегородки.
- Торцы плашмя-стойки касаются боковых граней двух обычных стоек. Ни одна доска не входит в другую.

Положение приёмного узла вычисляется из источника 2D-графа и направления внешней стены. Два существующих регулярных элемента сетки в зоне узла или одна стойка в центре зазора **удаляются из производной сборки**, чтобы не происходило наложения. Специальные стойки углов/проёмов не удаляются; при коллизии команда отклоняется, вместо создания опасной модели.

Соединения: \`left ↔ flat\`, \`right ↔ flat\`, \`flat ↔ partition end stud\`. У каждой из трёх деталей стабильный ID \`:partition-backing-...-left/-right/-flat\`. Внутренние Т- и крестообразные узлы остаются в прежней логике, они не получают лишней внешней опоры.

## Что сохраняется

Канонический \`building.floorPlan.graph\` и исходные 3D-входные параметры **не мутируют**. Производная \`assembly\` пересчитывается из JSON; открытие старого проекта заменяет старую конструкцию на исправленную. Размеры внешнего периметра, двери, Undo/Redo и горизонтальное сечение сохраняются. Новая версия приложения 0.1.19.

## Проверки

- Unit: число деталей (3 на наружное примыкание), ориентация \`roll=90°\`, координаты и реальные 3D-грани касания, отсутствие взаимного проникновения, замена нормальной стойки на шаге 600 мм, импорт/детерминированная сборка, внутренние Т- и крестообразные узлы.
- Unit горизонтального разреза: для кладовой в гараже 10×7 м — **6** элементов в двух каналах на высоте 1200 мм: 4 обычных стойки с площадью 45×145 и 2 плоских с площадью 45×100; верхние обвязки проверяются отдельно.
- Browser regression Chromium: на высоте Y=1200 у четырёх наружных деталей плюс двух плоских стоек подтверждаются 6 реальных сечений и сохранение JSON. Скриншот \`34-haun-three-stud-channel-1200.png\`.

**Статус проверки определяется исключительно фактическим GitHub Actions для коммита.** Тесты не являются нормативным расчётом крепления, прочности или устойчивости. Тип и количество гвоздей, огнестойкость и региональные строительные нормы — отдельные проектные задачи; \`engineeringStatus='not_evaluated'\`.

## Регламент
Работаем в \`sigma4\` от зафиксированного SHA, без force и reset. Один целевой этап, канонический JSON, детерминированный генератор, тесты + TypeScript + сборка + Chromium. Предыдущие версии и история сохраняются. После проверки — приёмка пользователем.
