# SIGMA4 v0.1.24 — S18. Независимая проверка сборки каркасных стен

**Дата:** 2026-11-06.
**Исходный Git HEAD (ветка \`sigma4\`):** \`d2ea90b8bea43f5c38edca6faf0c2374eb817f31\` (v0.1.23).
**Этап:** 5 из согласованной последовательности аудита конструкций Larry Haun.

## Цель

Существующий \`FrameValidator\` проверяет размеры и расположение отдельных элементов, а также ряд специальных узлов, но не даёт общей независимой оценки контактов и опирания **всех деталей конечной сцены**. Поскольку исходный JSON — единственный источник истины, проверка не изменяет ни исходный план, ни производные \`assembly.elements\`, а возвращает \`ValidationIssue[]\` с кодами и точными ID деталей.

## Реализовано

- \`frame-structural-validator.ts\`: независимые габаритные объёмы каждой доски в мировых координатах (мм), на основе ориентации quaternion, позы, поворота и положения стены. Геометрия согласована с визуализатором \`projectToScene\`, но не пользуется его готовым результатом проверки столкновений.
- **Связи:** проверка ID, запрет самоссылок/дубликатов, симметрия связей, подтверждение физического контакта граней между верхними нахлёстами и приёмными каналами Хона.
- **Коллизии:** разделение касания граней и положительного пересечения объёмов; контроль физических наложений вертикальных стоек, jack/king/cripple и rolled nailers; отдельно второго верхнего слоя обвязки. Геометрические пересечения на одной стене приводят к ошибке \`STRUCTURAL_TIMBER_COLLISION\`.
- **Нижнее опирание:** полные стойки, king, jack, нижние короткие стойки обязаны касаться нижней обвязки; отсутствие регистрируется как \`STRUCTURAL_MISSING_BOTTOM_SUPPORT\`.
- **Верхнее опирание:** полные стойки и верхние короткие стойки должны касаться нижней грани первого верхнего слоя. Верхний слой должен иметь контакт с первым слоем; для Т-нахлёстов допускается частичное опирание на первый слой (оно не обязано покрывать весь проходящий участок на другой стене).
- **Проёмы:** каждая jack-стойка обязана физически касаться снизу перемычки; верхние короткие стойки стоят на перемычке, нижние подпирают подоконник. Сохраняются числовые проверки размеров/толщины/сечений, сделанные в S16.
- **UI:** блок «Геометрический контроль каркаса» показывает количество ошибок с префиксом \`STRUCTURAL_\`, отдельно от надписи «Инженерный расчёт: не выполнен».
- **Контрольная граница:** связанный прямоугольный 2D→3D каркас \`floorPlan.frame.built\`. Старые автономные 3D-документы не получают новые предположения о соединениях и проходят существующую проверку.
- **Валидация:** независимый модуль подключён в \`validateGeometry\`; итог \`validateProject\`/ProjectStore отклоняет новые неверные конструкции без изменения истории JSON.
- **Числовые допуски:** 0,05 мм при трансформациях и 0,15 мм для исключения плавающих артефактов при сравнении граней. Это **не строительный допуск** на допустимые щели.

## Регрессии

Файл \`frame-structural-validator.test.ts\` содержит сценарии:
1. Гараж 10×7 с внутренней Т/Г-перегородкой, верхними нахлёстами, дверью и окном с усиленной перемычкой.
2. Полная стойка поднята на 10 мм — нижняя/верхняя опора потеряна, валидация запрещает сборку.
3. Две полноразмерные стойки занимают один и тот же объём.
4. Второй слой верхней обвязки оторван от первого.
5. Односторонняя/несуществующая/самоповторяющаяся связь.
6. Оторванный трёхстоечный nailer при Т-узле.
7. Jack-стойка не касается перемычки.
8. Верхняя короткая стойка без опоры; нижняя не достигает подоконника.
9. Автономный старый 3D-режим сохраняется, инженерный статус остаётся \`not_evaluated\`.

Браузерная проверка: на реальном проекте 9×6→10×7 после редактирования двери/окна проверяется нулевое число структурных ошибок, сохранённый JSON, 3D-панель и снимок \`40-stage5-structural-contact-validation.png\`.

## Ключевые ограничения

**Валидатор не является инженерным расчётом несущей способности.** Нельзя выводить \`engineeringStatus:'passed'\` из отсутствия найденных коллизий или зазоров. Для допуска к строительству по IRC/CSA требуются отдельные расчёты: опирание на фундамент, укосины и обшивка как диафрагмы жёсткости, крепёж и передача усилий, ветер/снег/сейсмика, материал с классом прочности и соответствие таблицам для конкретного пролёта. Наличие геометрически касающихся граней не доказывает достаточную несущую площадь.

Для будущих наклонных элементов проверка AABB должна быть заменена SAT/OBB либо точным пересечением solid meshes. Текущая S18 ограничена строго ортогональными 2D-конструкциями.

**CI-статус указывается исключительно по фактическому GitHub Actions конкретного коммита.**

## Регламент SIGMA4
