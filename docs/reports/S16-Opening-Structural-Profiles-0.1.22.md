# SIGMA4 v0.1.22 — этап 3: профили проёмов, опирание перемычек и нагрузки

Дата: 2026-11-06. Ветка: \`sigma4\`. Контрольная точка до правок: \`77aad0c3a1411b45bdc6c92f9eb554e639fe7957\` (v0.1.21).
Источники для конструктивной схемы: Larry Haun, *The Very Efficient Carpenter*, *Windows and Doors*, раздел *Framing Walls*, стр. 98–101; Larry Haun, *How to Build a House*, *Going Up*, стр. 94–96. Для ограничений применимости используется **2024 IRC R602.7**, включая R602.7(1), R602.7.4 и R602.7.5 (табличная проверка несущей способности — ОТДЕЛЬНАЯ незавершённая задача).

## Реализованные профили

1. \`bearing-double-preview\` (наружные окна и двери): две доски перемычки внутри стеновой глубины, полноценные king-стойки по краям, от 1 до 4 jack-стоек с каждой стороны. Автор задаёт только \`headerPreview: {depthMm,jackStudsPerSide}\` (90–610 мм; 1–4 шт.). Значения по умолчанию: 145 мм, по одной jack-стойке. Сборка и геометрические проверки **не подтверждают** табличную несущую способность.
2. \`garage-engineered-preview\` (ворота): \`garage.lintelPreviewDepthMm\` и \`garage.jackStudsPerSide\` регулируют глубину и опирание; собственный профиль и предупреждение об обязательном расчёте больших проёмов/portal-frame. Заводские монтажные зазоры остаются отдельными ограничениями.
3. \`nonbearing-flat\` (обычная дверь внутренней ненесущей перегородки): один плоский элемент над проёмом, две крайние стойки; без искусственного подбора несущего ригеля и без jack-стоек. Ограничения IRC R602.7.4 применяются в уже действующей проверке \`validatePlanFrame\`. Несущие внутренние перегородки **не заявлены** как поддерживаемый профиль.

## Как работает геометрия

- Канонический \`floorPlan.frame.openings\` и \`building.openings\` могут хранить \`headerPreview\` и \`designLoads\`. Schema \`sigma4-project.schema.json\` допускает их как строго типизированные необязательные поля; прежние проекты импортируются без миграции.
- \`applyLinkedHeaderProfile\` меняет только производные геометрические доски ПЛАНОВОГО 3D-каркаса: два слоя перемычки равномерно располагаются внутри глубины стены, их низ совпадает с верхом всех jack-стоек, king-стойки сдвигаются наружу на ширину дополнительных опор. Короткие стойки над увеличенной перемычкой пересоздаются от фактической высоты, независимо от сетки рядовых стоек.
- \`verifyOpeningFraming\` проверяет число элементов, длину и положение king/jack-стоек, контакт верха jack с низом перемычки, правильную длину/высоту обоих досок и отсутствие выхода за толщину стены. Для перегородки проверяет плоский head. Проверка встроена в \`validateGeometry\` для связанных планов.
- Интерфейс 2D-плана содержит секцию «Конструкция перемычки и нагрузки» в редакторе проёма. При сохранении значения проходят через обычную команду ProjectStore, без отдельных источников истины. Проверка валидности запрещает некорректные профили, отрицательные нагрузки и нагрузки для ненесущей перегородки.
- Для наружных проёмов допускается \`designLoads:{permanentKNPerM,variableKNPerM}\` (погонные нагрузки). Результат предварительного расчёта простейшей схемы при равномерной вертикальной нагрузке на пролёт L:
  \`w = permanent + variable\`, \`M = w*L²/8\` (кН·м), \`R = w*L/2\` (кН, на каждую сторону). Это расчёт **усилий**, НЕ несущей способности или предельного прогиба. Геометрический профиль, особенно ворота, остаётся **нерассчитанным** без полного набора расчётных данных, проверки свойств древесины, крепежа, нагрузочных сочетаний, колебаний/прогиба и опирания. \`engineeringStatus\` всегда \`not_evaluated\`; даже при заполненных нагрузках не выдаётся \`passed\`.
- Автономный legacy 3D-редактор без связанного 2D-плана не меняет геометрию перемычек: этап ограничен новым конструктором планового дома для безопасной обратной совместимости.

## Контроль качества

Новые тесты \`src/core/opening-profiles.test.ts\` проверяют стандартное наружное окно; настраиваемое окно с 235-мм перемычкой и двумя jack-стойками; физический контакт с опорами в 3D; гараж с парой опор на сторону; ненесущую перегородку; ошибки профиля/нагрузок; импорт JSON; горизонтальное сечение. \`scripts/browser-smoke.mjs\` проверяет реальные поля настройки внешнего окна, сохранение профиля и нагрузок, маркированное \`not_evaluated\` и скриншот \`38-stage3-header-profile-235mm-jacks2.png\`.

**Фактический статус тестов фиксируется GitHub Actions для соответствующего коммита.**

## Остаётся перед допуском к строительству

- Привязать проект к выбранной юрисдикции (IRC 2024/местные поправки/канадские нормы), классу/породе пиломатериалов, режиму службы, количеству этажей и нагрузочной схеме; подобрать размеры по соответствующим таблицам R602.7 и R602.7.5 или выполнить инженерный расчёт. Учитывать требуемые полноразмерные стойки для ветровой нагрузки, крепёж, опирание, фундамент и жёсткость portal frame.
- Не считать 45-мм пиломатериал точным эквивалентом американских nominal 2x изделий (у них другая фактическая толщина). Даже совпадение геометрии и вычисленных усилий не доказывает соответствие IRC.
