# SIGMA4 v0.1.23 — S17: геометрические привязки при редактировании плана

**Дата:** 2026-11-06. **Ветка:** \`sigma4\`. **Зафиксированное исходное состояние:** \`268d405a36b40ebc6b7077f310c65456d466d64d\` (v0.1.22).

## Обнаруженный дефект

\`PLAN_FRAME_RESIZE\` ранее изменял только точки \`floorPlan.exterior\`. Точки \`floorPlan.graph.nodes\` и конечные точки legacy \`interiorWalls\`, совпадающие с бывшей границей дома, оставались на прежних координатах. В результате каркасный узел мог потерять привязку к наружной стене, хотя план 2D внешне выглядел похожим. Кроме того, при сдвиге Т-узла вдоль зависимой ветки существующая дверь могла сдвинуться по самой стене из-за изменения её локального начала. Разбиение стены под дверью оставляло прежнюю \`wallId\` у проёма, даже если он попадал на новый участок.

## Реализация

### 1. Канонические точки с геометрическими ограничениями
\`resizePlanWithBoundNodes\` переносит наружную границу **и** каждый графовый узел, находившийся на соответствующей перемещаемой стороне исходного прямоугольника. Связанные отрезки обновляются ссылками на те же \`node.id\`; Т- и X-узлы сохраняются и не дублируются. Для legacy \`interiorWalls\` переносятся обе конечные точки, физически совпадающие с изменяемой границей. Внутренние/свободные точки остаются в прежних миллиметровых координатах — комнаты не масштабируются произвольно. Если новая граница проходит через существующую стену, исходный валидатор отклоняет команду и **не меняет** документ.

### 2. Привязка дверей, окон и ворот к исходной стене
\`preservePlanOpeningAttachments\` связывает старую и новую геометрию по \`wallId\`, направлению и расположению сегмента. Политика:
- Изменение наружных размеров: \`positionUmm\` относительно начала **своей** стены сохраняется; проём следует за этим началом, если оно движется с наружной границей.
- Перемещение существующей внутренней стены: при сдвиге точки начала *вдоль* зависимой стены дверь сохраняет физическую продольную координату, а \`positionUmm\` пересчитывается. При нормальном перемещении стены дверь следует за стеной.
- Автоматическое разбиение отрезка новой точкой или Т-узлом: если **весь** проём находится на одном из новых фрагментов, его \`wallId\` переносится на этот фрагмент, а \`positionUmm\` пересчитывается без перемещения проёма в плане.
- Если новый узел перерезает существующую дверь, удаляется стена с проёмом или больше нет допустимого сегмента — выдаётся \`PLAN_ATTACHMENT_CONFLICT\` с ID проёма. Изменение отклоняется **атомарно**. Не включаются эвристики автоматического смещения/сокращения двери ради обхода валидатора.

### 3. Интеграция в ProjectStore
Используется в \`PLAN_FRAME_RESIZE\`, \`PLAN_MOVE_POINT\`, командах графа (разделение, создание, перемещение, удаление), \`PLAN_ADD/UPDATE/REMOVE_INTERIOR_WALL\`, \`PLAN_MOVE_INTERIOR_WALL\`, \`PLAN_SET_INTERIOR_CLEARANCE\`. Хранится только авторский JSON: узлы/отрезки, расположение проёмов, параметры. Производная \`assembly\` восстанавливается обычным детерминированным генератором. История Undo/Redo и импорт/экспорт остаются источником проверки непротиворечивости.

## Тесты

\`src/core/plan-attachment-constraints.test.ts\` покрывает:
- Гараж 9×6 м с угловой кладовой, T-соединением и дверью D01 → изменение размеров до 10×7 м и контроль граничных общих точек, окна, D01, горизонтального сечения.
- Перемещение стены с присоединённой боковой веткой и дверью: относительное расстояние проёма меняется 1200→1450 мм, физическое положение сохраняется; графовый T-узел не распадается.
- Удлинение стены от наружной границы: локальное расстояние проёма от этой границы сохраняется.
- Разделение стены новым Т-узлом: проём автоматически переходит на подходящий сегмент; пересечение двери новым узлом отклоняется без изменений.
- Уменьшение габаритов через существующую внутреннюю стену или гаражные ворота: отклонение, JSON и ревизия не изменены.
- Совместимость с legacy внутренними отрезками без графа; детерминированный экспорт-импорт; Undo/Redo.

Браузерная регрессия через реальный UI: после настройки окна с перемычкой и построения кладовой меняются габариты 9×6→10×7, проверяются все авторские привязки и готовый 3D-каркас. Скриншот \`39-stage4-resize-bound-partition-10x7.png\`.

## Область и ограничения

- Редактор поддерживает осевые ортогональные стены и прямоугольный замкнутый внешний контур для планового 3D-каркаса. Геометрическое редактирование L-/U-образных внешних контуров и автоматический перенос объектов по произвольным диагональным/криволинейным связям пока не добавлен.
- Если пользователь сдвигает границу внутрь настолько, что она пересекает стену/проём, изменение **отклоняется**; автоматически разрушать или масштабировать помещение нельзя.
- Правила геометрических связей не означают инженерную оценку несущей способности: \`engineeringStatus\` остаётся \`not_evaluated\`.
- Итоговый статус проверок фиксируется только фактическим GitHub Actions для коммита; никаких заявлений об успехе до проверки.

**Регламент:** источник JSON единственный, работа в отдельной ветке \`sigma4\`, точка до правок записана, без force reset и перезаписи Git-истории, коммит после каждого логически завершённого изменения, пользовательская визуальная приёмка перед этапом 5.
