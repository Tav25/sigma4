# SIGMA4 — обязательные правила работы с исполнителем

Версия правил: 1.0  
Применяются к каждому ТЗ проекта SIGMA4, начиная с базы конструктора v0.0.14.

## A. Git и безопасность исходников
1. Перед работой показать `git status --short`, `git branch --show-current`, `git log -1 --oneline` и фактическую версию приложения.
2. Работать **только в отдельной ветке `sigma4`**, созданной от проверенной базы v0.0.14; прежние ветки и коммиты не переписывать. Если дерево грязное, ветка уже существует или базовая версия не совпадает — остановиться и представить факты. Не делать `reset --hard`, force push, удаления истории и скрытого stash.
3. Один законченный этап — один осмысленный коммит после проверок. Предоставлять SHA. Созданный коммит не означает приёмку заказчиком.
4. Перед рискованной миграцией — отдельная контрольная точка. Не переносить код поздних сломанных версий без специального разрешения.

## B. Порядок работы
5. Выполнять только назначенное ТЗ. Не добавлять крышу, новые стены, декоративные функции или независимые рефакторинги «заодно».
6. Сначала описать затрагиваемые файлы, инварианты и тесты. Ошибку воспроизвести проваливающимся тестом до исправления; после — тем же тестом подтвердить решение.
7. JSON-файл — каноническая цифровая модель проекта. Изменять проект только через команды и проверку. Three.js не является хранилищем проекта и не меняет структуру непосредственно.
8. Разделять авторские параметры и производные данные. Каждая физическая доска в согласованном снимке модели имеет уникальный ID, размеры, координаты, ориентацию, назначение и связи. Производные данные детерминированно восстанавливаются; нельзя иметь два противоречащих источника координат.
9. Правила делятся на: структуру JSON, геометрию/конструктивную схему и инженерную прочность. Геометрически корректный проект **не объявлять** расчётно безопасным без расчётов нагрузок, крепежа и применимых нормативов.

## C. Качество и доказательства
10. Запрещены необработанные исключения, битая UTF-8, самопроизвольное изменение параметров соседних объектов и регрессии ранее принятых функций.
11. Тесты должны независимо сравнивать расчётные значения с фактическими Mesh/экспортом. Не тестировать функцию её собственным результатом. Добавлять тесты на отрицательные сценарии.
12. Перед отчётом выполнить lint, typecheck, unit/integration tests, build; для затронутого 3D — браузерную проверку, скриншоты и реальные мировые координаты.
13. Отчёт о завершении обязан содержать: ветку, SHA, список файлов, сделанное/не сделанное, число новых и всех тестов, вывод проверок, подтверждение отсутствия регрессий, воспроизводимые артефакты, известные ограничения.
14. Если тесты не проходят, диагностика неполна или ошибка сохраняется, писать **«не выполнено»**, а не «готово». Запрещена подмена доказательств уверенным утверждением.
15. После выполнения **остановиться до приёмки**. Следующий этап только по отдельному ТЗ.

## Обязательный блок в конце каждого следующего ТЗ
**Правила SIGMA4:** проверить ветку `sigma4` и базовый SHA; работать только в рамках ТЗ; JSON — единственный источник истины; сначала тест/диагностика, затем правка; не ломать UTF-8 и прежние функции; показать результаты lint/typecheck/tests/build и фактическую 3D-проверку; после успешных проверок — коммит и SHA; остановиться для приёмки.
