# SIGMA4 — архитектурные решения v1

## Принцип
Один версионируемый файл `*.sigma4.json` — цифровая модель проекта, а Three.js лишь отображает материализованное состояние. **Не** хранить параллельно независимые координаты окна, его маркера и 3D-меша.

## Слои
1. ProjectDocument (`source`) — вводимые параметры, материалы, стены, проёмы и привязанные свойства маркеров.
2. FrameGenerator — чистая детерминированная функция `source + ruleset -> assembly.elements` (каждая доска с ID, габаритами, координатами, ориентацией и ролью).
3. ProjectValidator — независимая проверка структуры, связей, геометрии и согласованности `source`/`assembly` с явными кодами ошибок.
4. ProjectStore — применение команд только через `candidate -> generate -> validate -> commit`, история/undo/redo позднее.
5. SceneView — чтение `assembly.elements`, отрисовка, перевод взаимодействия в команды, без владения геометрическим состоянием.
6. Инженерная верификация по нагрузкам и нормам — отдельный будущий уровень со статусом `not_evaluated`.

## Сохраняемый файл
Документ может содержать исходные данные и материализованный список физической древесины в одной JSON-структуре. При загрузке валидатор обязан проверять актуальность производной части; при несогласованности открывать в режиме диагностики, но не считать её проверенной моделью. Не доверять сохранённым `valid: true` и не объявлять соответствие строительным нормам без дополнительных инженерных проверок.

## Версионирование
Отдельно версионировать `schemaVersion`, `rulesetVersion`, `generatorVersion`; миграции явные и обратимые, не изменять старые проекты молча.

## Этапы
- S01: ветка, правила, контракт JSON, базовый валидатор, roundtrip без изменения отображения.
- S02: ProjectStore и атомарные команды редактирования.
- S03: переключить SceneView на `assembly.elements`, независимо проверить мировой XYZ и текущие доски.
- S04: привязанные маркеры, окна и двери как производные представления, браузерные тесты.
- S05: расширение на несколько стен и узлы с отдельными наборами проверок.

Каждый этап принимается отдельно. Не перенести сломанные решения из веток 0.0.18.x автоматически.
